# ClaimSense — Test Fixtures

> The saved pages, PDFs, records, queries and tiny model artefacts that let every test run offline, with no real data and no network. Covers what each fixture is, where it came from, which tests use it, the privacy rule that decides whether a real document may be committed, and how fixtures are refreshed when a site changes.

**Author:** Diya Shrivastava · **Owning PR:** 3 (layout, collector fixtures, fixture manifest); every later PR adds the fixtures its tests need · **Status:** Planned

**Related:** `testing/test-strategy.md` §1, §8, `testing/leak-probe-tests.md` §3, `data/collection-runbook.md` §1, §7, `data/terms-of-use-audit.md`, `data/anonymisation-spec.md` §7, `pipeline-interface.md` §8, NFR-02, NFR-08, NFR-09, risks R2, R5, R14.

---

## 1. Rules

1. **Committed fixtures contain no real personal data.** This is the rule everything else follows from. Indian awards name complainants and give addresses; committing one to a public repo would republish exactly what the anonymiser exists to remove (R5), and only FSPO is cleared in the terms audit (R2).
2. **Synthetic by default, real only when allowed.** A fixture is one of three kinds (§2). A real document is committed only if its source's redistribution box is ticked in `data/terms-of-use-audit.md` **and** it contains no personal data.
3. **Small.** Each PDF ≤ 200 KB, each HTML page ≤ 300 KB, whole `tests/fixtures/` ≤ 20 MB. Big files slow every CI run.
4. **Every fixture is listed** in `tests/fixtures/FIXTURES.yaml` with kind, origin, capture date, hash and the tests that use it. CI fails on an unlisted file or a hash mismatch.
5. **Fixtures are not edited in place.** A changed fixture gets a new file name (`_v2`); the old one stays while any test uses it.
6. **No live URLs are fetched.** URL strings appear only in `urlmap.yaml` files, which map a URL to a local file.

## 2. Fixture kinds

| Kind | What it is | Allowed for | How made |
|---|---|---|---|
| **Saved** | A page or document captured from a source, trimmed, unchanged otherwise | Listing/index pages with no personal data; robots.txt; documents only from a source cleared for redistribution whose published text is already anonymised | `scripts/fixtures/capture.py --source fspo --url …` (one polite request, records date and hash) |
| **Saved-redacted** | A saved listing page with names, case titles and references replaced by fictional ones, keeping HTML structure, classes and pagination markup | CIOINS and FOS listing pages (needed to test parsers before those sources are cleared) | `scripts/fixtures/redact_html.py` + manual review; reviewer initials in `FIXTURES.yaml` |
| **Synthetic** | Text written for the test, laid out to mimic a source's real headings and quirks | All decision documents for CIOINS and FOS; all PII, leak, label and pipeline fixtures | Plain text/JSON by hand; PDFs generated by `tests/fixtures/_build/make_pdfs.py` (reportlab), scans by rasterising and adding noise |

All synthetic people, hospitals, places and reference numbers are fictional and deliberately implausible on inspection (e.g. hospital "Lakeside Demo Nursing Home", PIN codes from an unused range), so no fixture can be mistaken for a real case.

### Local-only real samples (not committed)

`tests/fixtures_local/` is git-ignored. It holds a handful of real documents per source and office, copied from `data/raw/`, used by `local_data` regression tests for the parser and segmenter. It is the bridge between synthetic layouts and real ones: when a real layout breaks the segmenter, a **synthetic** fixture with the same structure is added to the committed set.

### Fake transport

`tests/stubs/fake_http.py` serves files according to each `urlmap.yaml`:

```yaml
# tests/fixtures/collect/fspo/urlmap.yaml
"https://www.fspo.ie/decisions/?product=health&page=1": list_p1.html
"https://www.fspo.ie/decisions/?product=health&page=2": list_p2.html
"https://www.fspo.ie/robots.txt": robots.txt
"https://www.fspo.ie/decisions/example-001.pdf": decision_health.pdf
"https://www.fspo.ie/decisions/missing.pdf": "@404"
```

Any URL not in the map raises `UnmappedURL`, so a collector that tries to reach somewhere unexpected fails loudly. URLs are illustrative; real paths are filled in when each listing page is captured. The transport records every request with its mocked timestamp and headers, which is how NFR-08 (interval ≥ 2 s, one connection, User-Agent with contact email) is asserted.

### Resume scenarios (`test_resume.py`)

| Scenario | Setup | Expected |
|---|---|---|
| Second run | Run collector twice on the same map | Second run: `stored 0`, manifest row count unchanged (FR-03a) |
| Interrupted | Fake transport raises after the 3rd document | Re-run completes; no duplicate `doc_id` or hash; at most one `.partial` cleaned up (FR-03b) |
| Tampered file | Change one byte of a stored file | `verify` reports a hash mismatch; next run re-downloads it |
| Same file, two URLs | Two URLs map to the same PDF | Second logged `duplicate` |

## 5. Parse, segment, label and anonymise fixtures (PR 5, PR 6)

### Parse (FR-04)

| Fixture | Expected |
|---|---|
| `text_layer.pdf` | Non-empty text, OCR not called |
| `scanned.pdf`, `scanned_rotated.pdf` | Tesseract path used; non-empty text; key phrase found |
| `unreadable.pdf` | Both paths fail → logged with reason, counted, not silently dropped |
| `two_column.pdf` | Reading order preserved (left column before right) |
| `header_footer_repeat.pdf` | Lines on ≥ 50% of pages removed |

### Segment (FR-05)

One synthetic `.txt` per layout quirk listed in `data/segmentation-rules.md` §3, each with an `expected/<name>.json` giving section spans. The `bad_*` files must be dropped with the matching reason code (`order_violation`, `missing_findings`, `marker_in_facts`, `non_english`). Every new layout found in real data adds one synthetic file here.

### Label (FR-06)

`label/wording.yaml` holds outcome sentences per source and office style, each mapped to `upheld`, `partially_upheld`, `rejected` or `EXCLUDE` (non-entertainable, withdrawn, settled before award), plus a few unmapped wordings that must produce a logged entry and no label.

```yaml
- source: cioins
  text: "The complaint is partly allowed and the insurer is directed to pay Rs. 0,00,000/-"
  expect: partially_upheld
- source: fspo
  text: "Outcome: Rejected"
  expect: rejected
- source: cioins
  text: "The complaint is not entertainable under Rule 14"
  expect: EXCLUDE
```

### Anonymise (FR-07, NFR-02)

| Fixture | Purpose |
|---|---|
| `entities/E01–E16.txt` + expected | One input per entity in `anonymisation-spec.md` §2, with the exact expected output |
| `kept.txt` | Insurer and TPA names, conditions, amounts, month/year dates, state names must survive |
| `consistency.json` | Same person in all four segments → same `[PERSON_n]` |
| `allowlist.txt` | "Parkinson's disease" kept; "Mr Parkinson" replaced |
| `overlap_spans.txt` | Longer span wins; `[PERSON]` beats `[PROVIDER]` on ties |
| `pin_vs_amount.txt` | Six-digit amount not near address cues is **not** replaced; PIN with address cue is |
| `pii_scan_clean.jsonl` / `pii_scan_planted.jsonl` | Post-check regex finds 0 on clean; finds every planted phone, email, PIN, postcode, policy number, Aadhaar/PAN format, honorific + name, `Dr` + name |

All identifiers in these files are fictional. Government-ID-format strings use values that fail real checksums or official formats beyond the regex shape.

## 6. Leak-probe fixtures (PR 6, PR 7, PR 13)

Records are JSONL with `doc_id`, `source`, `marker_rule`, `complaint`, `insurer_position`, `findings`, `award`, `facts_text`, `decision_date`, `label`. Planted files are the clean records with exactly one violation each, and an `_planted` field describing it so the test can check the probe reports the right location.

| Fixture | Content | Probe expectation |
|---|---|---|
| `clean.jsonl` | 20 correctly segmented synthetic records across three sources | All L1 probes pass |
| `planted_sentence.jsonl` | Award sentence in complaint; findings sentence with shuffled anonymiser indices and changed amounts; FOS quoted provisional finding | Sentence probe fails on each |
| `planted_ngram.jsonl` | 20-token findings span in insurer position; a 12-token span (below n) | Fails on the first; passes on the second |
| `policy_quote_allowed.jsonl` | Same exclusion clause quoted in insurer position and findings | n-gram probe passes; allowlisted hit counted |
| `planted_marker.jsonl` | "My final decision" mid-sentence; "AWARD" heading in facts; `निर्णय` in facts; FSPO "the insurer's decision" (must **not** fail) | Marker probe fails on the first three only |
| `lexicon.jsonl` | Known lexicon counts per record, balanced and unbalanced label sets | Counts match; unbalanced set emits `CHECK` |
| `split_clean.parquet` / `split_planted.parquet` | Dates on the split boundaries (2023-12-31, 2024-01-01, 2024-12-31, 2025-01-01); planted 2025 record in train | Clean passes; planted fails |
| `dedup_clean.jsonl` / `dedup_planted.jsonl` | Planted exact copy across train/test; near copy across val/test; a cluster where the later copy was kept | Each planted case fails |
| `retrieval_index.jsonl` | 40 synthetic precedents spread 2019–2025, including two on the same date as a test query and the query document itself | Property test: nothing on or after `before`; query doc excluded |

## 7. Dataset, pipeline and app fixtures (PR 7 onward)

### Mini-dataset (`dataset/mini/`)

60 synthetic processed records (20 per split, all three labels, all three sources, all `RejectionReason` values) matching `data-schema.md` §4 exactly. Used by baseline smoke tests, `test_dataset_build.py` (rebuild gives the same hash), `test_report_command.py` and the app's Data Explorer test. Regenerated only by `scripts/fixtures/make_mini_dataset.py` with a fixed seed.

### Pipeline queries (`pipeline/queries.yaml`)

| Group | Count | Expected |
|---|---|---|
| On-topic, confident | 6 | Not abstained; label in enum; `probability == class_probabilities[label]` |
| On-topic, borderline (stub logits near uniform) | 3 | `LOW_CONFIDENCE`; precedents present; label hidden |
| Too short | 2 | `INPUT_TOO_SHORT` |
| Non-English (Hindi, Gujarati) | 2 | `UNSUPPORTED_LANGUAGE` |
| Off-topic: motor claim, recipe, general question | 3 | `OFF_TOPIC` (FR-17b) |
| Rare topic with no similar precedents in the toy index | 2 | `NO_PRECEDENTS` |
| Precedence: short **and** off-topic | 1 | `INPUT_TOO_SHORT` (step order) |
| Latency set | 20 | Reused by `bench_latency.py` against real artefacts locally |

### Explainer and NLI stubs

| Fixture | Contains | Tests |
|---|---|---|
| `explainer/supported.json` | Three sentences each citing a retrieved precedent | All kept (stub NLI scores above `min_entailment`) |
| `explainer/injected_unsupported.json` | One sentence the cited excerpt does not support | That sentence dropped `LOW_ENTAILMENT` (FR-16b) |
| `explainer/no_cite.json`, `unknown_cite.json`, `advice_phrase.json` | Structural failures S2–S4 | Dropped with `NO_CITE`, `UNKNOWN_CITE`, `ADVICE_PHRASE` |
| `explainer/all_unsupported.json` | No supported sentence | `explanation == []` + warning `NO_SUPPORTED_EXPLANATION` (FR-16c) |
| `explainer/malformed.json` | Invalid JSON | Treated as no supported sentences, warning logged |
| `nli_scores.yaml` | Scores keyed by (precedent id, sentence hash) | Read by `StubNLI` |

### Tiny model artefacts (`models/`)

| File | Purpose |
|---|---|
| `stub_classifier.json` | Fixed logits per query id, so abstain thresholds can be hit deliberately |
| `calibrator_tiny.pkl` | Temperature scaler with a known temperature; `test_calibration_math.py` checks outputs by hand-computed values |
| `thresholds.json` | `abstain.threshold` and `fit_split: "val"` |
| `index_tiny/` + `index_meta.json` | Toy index over `retrieval_index.jsonl` using the hashing embedder |
| `meta.json` | Versions that match `index_meta.json`; a mismatched copy `meta_mismatch.json` triggers `ArtifactMismatchError` |

None of these are trained models; real adapters and indices are never committed.

## 8. Refreshing fixtures when a site changes (R14)

1. A collector fails on a real run or `--dry-run` (e.g. listing returns 0 items).
2. Capture the new page once with `scripts/fixtures/capture.py` (polite, one request, User-Agent set).
3. Redact it if it is a CIOINS or FOS page; review by hand.
4. Save as `<name>_v2.html`; **keep** the old fixture. Add a test case for the new layout; the old case stays, so the parser handles both.
5. Update `FIXTURES.yaml` and `urlmap.yaml`.
6. Fix the parser until both cases pass.
7. Note the change in the PR description and, if it changes what is collected, in `data/collection-runbook.md` §6.

Old fixtures are removed only when the parser deliberately drops support for that layout, in a separate commit.

## 9. Fixture manifest — `tests/fixtures/FIXTURES.yaml`

```yaml
- path: collect/cioins/month_2023-05.html
  kind: saved-redacted
  source: cioins
  captured: 2026-11-20          # filled at capture time
  sha256: "…"
  contains_personal_data: false
  redaction_reviewed_by: DS
  used_by: [tests/collect/test_cioins_listing.py, tests/collect/test_manifest_schema.py]
  notes: "Office codes kept; complainant names and award titles replaced with fictional ones"

- path: leak/planted_sentence.jsonl
  kind: synthetic
  contains_personal_data: false
  used_by: [tests/leak/test_sentence_probe.py]
  notes: "3 planted L1 violations; see _planted field"
```

`tests/test_fixtures_manifest.py` (runs in CI) checks that every file under `tests/fixtures/` is listed, every hash matches, every `used_by` path exists, `contains_personal_data` is `false` for all entries, and no file exceeds the size limits in §1.

## 10. Checklist when adding a fixture

- [ ] Kind chosen per §2; real documents only from a source cleared for redistribution
- [ ] No real names, addresses, phone numbers, references or IDs; fictional values look fictional
- [ ] Within size limits
- [ ] Listed in `FIXTURES.yaml` with hash and `used_by`
- [ ] For a data guard (leak, PII): both a clean and a planted version exist
- [ ] Synthetic PDFs regenerate byte-identically from `_build/make_pdfs.py`
